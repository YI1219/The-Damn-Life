# The Damn Life 项目计划书 V0.4

---

## 1. 简介

### 1.1 终极目标

The Damn Life 的终极目标是，制作一个每个人都可以使用的本地 AI 助手。最终形态是：

- 本地一个 Model on Chip（芯片级大模型）
- 可以调用各大远程模型
- 可以访问各个系统的工具
- 可以多个系统联动（远程操作、指令交互）
- 每人只需要一个本地 AI 助手即可

### 1.2 系统组成

The Damn Life 由以下几个大部分组成：

| 组件 | 说明 |
|------|------|
| 环境管理器 | 运行在各设备上的软件，负责通信、技能执行、UI 交互 |
| 本地个人 AI 助手 | 运行在硬编码芯片级别的大模型上（软件形态作为过渡） |
| 各扩展终端 | AI 眼镜、AI 手表等终端智能设备 |

---

## 2. 环境管理器

环境管理器是系统的核心软件，运行在用户的 PC、NAS 或未来硬件模块上。它负责任务调度、工具调用、多设备协同。

### 2.1 离线优先设计

**核心原则**：本地能力优先，联网能力增强。

**能力分级**：

| 级别 | 能力 | 说明 |
|------|------|------|
| 核心能力 | 本地对话、已安装 Skill、本地模型推理 | 必须离线可用 |
| 增强能力 | 远程模型调用、内容市场、同步多设备 | 联网时可用 |

**离线降级策略**：
- 网络断开时，UI 明确提示“离线模式”
- 远程调用请求自动转为本地模型处理
- 需要联网的操作（如下载内容）置灰并提示
- 恢复联网后自动同步状态

**用户控制**：
- 用户可设置“始终离线模式”（隐私/安全场景）
- 用户可设置“仅局域网模式”（家庭内网场景）

### 2.2 核心通信层

负责设备发现、设备间通信、跨系统协议适配。

**技术方案**：
- 设备发现：mDNS（Bonjour/Avahi）用于局域网设备发现
- 设备通信：WebSocket over TLS，简化实现，兼容性好
- 协议适配：插件化架构，支持 Home Assistant、MQTT 等开放协议
- 私有性：体现在身份体系、权限模型、数据不出本地，而非通信协议本身

**分期规划**：

| 版本 | 通信能力 |
|------|----------|
| V0.5 | 单机模式，无设备间通信 |
| V1.0 | 局域网通信（IP + mDNS 发现） |
| V2.0 | 互联网 P2P 通信（libp2p + NAT 穿透 + 中继） |

**P2P 通信实现策略（V2.0）**：
- 技术选型：libp2p（成熟库，支持多传输协议）
- 连接建立流程：
  1. 尝试直接连接（IP + 端口）
  2. 尝试 UPnP 端口映射
  3. 尝试 NAT 穿透（STUN）
  4. 回退到中继服务器（TURN）
- 中继策略：
  - 项目方提供中继服务器（有限带宽，免费使用）
  - 用户可自建中继服务器（开源方案）
  - 企业版可购买专用中继
- 连接维护：心跳保活（每 30 秒），网络切换时自动重连

### 2.3 技能运行时（Skill Runtime）

负责调用工具、执行指令。Skill 是环境要素交互方式的打包形式。

**Skill 定义**：
- 输入规范：JSON Schema 定义
- 执行逻辑：Python/JavaScript 脚本或本地命令
- 输出规范：结构化数据返回给 AI 助手

**Skill 类型**：
- 本地工具：文件操作、命令行、应用控制
- 智能家居：Home Assistant、MQTT 设备
- 网络服务：API 调用（天气、日历、邮件等）

**Skill 安全**：
- 沙盒运行：Skill 运行在 WebAssembly 或 Docker 容器中
- 权限模型：Skill 需声明所需权限（文件、网络、设备）
- 用户审批：首次运行需用户确认权限
- 代码审查：上传市场需人工审核

**分期规划**：

| 版本 | Skill 能力 |
|------|------------|
| V0.5 | 用户手动配置的本地命令 |
| V1.0 | 官方 Skill 库 + 用户自建 |
| V1.5 | Skill 市场（用户上传/下载，分免费/付费） |

### 2.4 用户界面服务

可插拔 UI，初期固定，后期支持用户定制。

**UI 形态**：
- V0.5：Web 界面或命令行
- V1.0：桌面应用（Electron/Tauri）
- V2.0：移动端 App（Android/iOS）

**首次使用引导（V1.0）**：
1. 欢迎页：介绍本地 AI 助手的概念
2. 模型下载：选择并下载第一个本地模型
3. 首次对话：与 AI 进行简单对话
4. Skill 演示：展示一个内置 Skill（如“打开浏览器”）
5. 远程增强：介绍远程模型和 Token 订阅
6. 完成：进入主界面

可选步骤：
- 导入已有配置（从其他 AI 工具）
- 连接智能家居设备
- 配置多设备同步

**交互方式分期**：

| 版本 | 交互能力 |
|------|----------|
| V1.0 | 文字对话 + 固定指令 |
| V2.0 | 语音唤醒 + 语音指令 |
| V3.0 | 视觉识别（摄像头场景识别） |
| V4.0 | VLA 级别行为捕捉（技术预研） |

### 2.5 使用统计与洞察（V1.0+）

统计面板内容：
- Token 消耗趋势（日/周/月）
- 调用分布（本地 vs 远程）
- Skill 使用排行
- 模型响应时间
- 节省成本估算（本地替代远程节省的 Token）

洞察建议示例：
- “您本月远程调用较多，是否考虑下载 XXX LoRA 提升本地能力？”
- “Skill Y 使用频率低，是否考虑取消订阅？”
- “您已连续 30 天使用本地模型，累计节省 XXX Token”

**数据存储**：所有统计数据**本地存储**，不上传云端。用户可选择性贡献匿名数据（需明确授权）。

### 2.6 故障恢复与容错

**模型崩溃**：
- 自动重启推理进程
- 保留对话上下文（检查点机制）
- 降级到远程模型（如果可用）

**训练中断**：
- 检查点保存（每 100 步保存一次）
- 恢复时从中断点继续
- 训练数据事务性写入（防止损坏）

**硬件热插拔**：
- 硬件模块插入时自动检测并加载
- 拔出时自动降级到软件模型
- 运行中任务无缝迁移（如可能）

### 2.7 数据收集与本地训练

积累有效数据，在闲时进行 LoRA 微调，产生更符合用户特征的个性化权重。

**数据收集**：
- 用户交互记录（本地存储，不上传）
- 用户可选择性贡献匿名数据换取 Token（需明确授权）

**本地训练**：
- 闲时检测（设备空闲 + 供电充足）
- 硬件检测（仅在有 GPU/NPU 时启用）
- LoRA 微调，产出个性化权重

**LoRA 训练模块详细说明（V1.5）**：

| 项目 | 说明 |
|------|------|
| 最低硬件 | NVIDIA GPU 6GB 显存 / Apple Silicon 16GB 统一内存 |
| 推荐硬件 | NVIDIA GPU 8GB+ / Apple Silicon 32GB+ |
| 不支持设备 | 无 GPU 设备（功能禁用） |
| 默认步数 | 500 步（约 30-60 分钟） |
| 学习率 | 2e-4 |
| 秩（Rank） | 16 |
| 目标模块 | q_proj, v_proj |
| 训练时机 | 用户可设置（仅闲时 / 立即开始 / 手动） |
| 训练数据 | 用户可选择数据范围（最近 N 天 / 全部） |
| 优先级 | 可降低训练进程优先级，减少前台影响 |
| 训练产物 | LoRA 权重文件（约 50-200MB），用户可命名、管理、上传 |

**分期规划**：

| 版本 | 训练能力 |
|------|----------|
| V0.5 | 数据收集框架（本地存储） |
| V1.0 | 训练调度器骨架（检测硬件，不实际训练） |
| V1.5 | LoRA 训练模块（有 GPU 用户） |
| V2.0 | 训练数据贡献（匿名上传换取 Token） |

## 3. 本地个人 AI 助手

### 3.1 软件形态（V0.5 - V1.5）

第一阶段以软件形态交付，运行在用户现有设备上。

**技术方案**：
- 推理引擎：llama.cpp（CPU/GPU）、MLX（Mac）、ONNX Runtime（Windows）
- 基座模型：Llama 3 8B、Qwen 2.5 7B/14B 等开源模型
- 量化精度：Q4_K_M 或 Q5_K_M（平衡质量与性能）

**模型能力**：
- 基础对话：日常问答、信息查询
- 工具调用：通过 Skill Runtime 执行操作
- 远程增强：复杂任务可切换到远程模型

### 3.2 硬件形态（V2.0+）

长期愿景是芯片级大模型，作为硬件模块交付。

**硬件路线**：

| 阶段 | 形态 | 说明 |
|------|------|------|
| 初期 | 树莓派扩展模块 | USB-C 供电 + PCIe/NVMe 接口，与 PC 配合使用 |
| 中期 | 自研 NPU 模组 | 定制芯片，更高能效比 |
| 长期 | Model on Chip | 独立芯片，可嵌入各种设备 |

**硬件与环境管理器的关系**：
- 纯软件模式：环境管理器直接调用 CPU/GPU 运行量化模型
- 硬件加速模式：检测到硬件模块后，将推理任务卸载到硬件
- 独立硬件模式：硬件自带简化版环境管理器，可独立运行

### 3.3 模型优化方案

参考上交大 ROMA 技术，使用 LoRA Expert 形式实现多场景适配。

**LoRA 应用场景**：
- 编程助手：针对代码生成优化的 LoRA
- 写作助手：针对长文本生成的 LoRA
- 智能家居：针对设备控制指令的 LoRA
- 个人助手：针对用户历史对话的个性化 LoRA

**LoRA 管理**：
- 本地存储多个 LoRA 权重
- 运行时根据场景动态加载
- 用户可上传/下载 LoRA 权重（通过内容市场）

## 4. 各扩展终端

### 4.1 终端类型

通过私有通信方式接入 AI 眼镜、AI 手表等终端智能设备，实现随时随地的 AI 助手陪伴。

**分期规划**：

| 版本 | 终端支持 |
|------|----------|
| V1.0 | PC + Android 手机 |
| V1.5 | iOS 手机 |
| V2.0 | AI 眼镜（开源厂商） |
| V2.5 | AI 手表 |
| V3.0 | 自研终端（如需要） |

### 4.2 私有通信协议

设备之间通过互联网点对点绑定，后续即便更换网络环境也不影响连接。

**终端模式定义**：
- 远程终端模式：终端作为输入/输出设备，推理在 PC/硬件模块完成，数据回传处理
- 独立模式：终端运行轻量版 AI，与主设备同步状态（V2.0+）

**通信技术方案**：
- 身份绑定：设备间共享密钥 + 身份证书
- NAT 穿透：STUN/TURN 协议（V2.0 实现）
- 数据加密：TLS 1.3 + 应用层加密

### 4.3 插件化架构

终端适配作为独立驱动插件，逐步增加。

**插件接口**：
- 设备发现：提供发现协议适配
- 消息收发：提供通信协议适配
- 能力协商：终端能力上报（屏幕尺寸、传感器等）

## 5. Token 经济模型

Token 是 The Damn Life 生态系统内的通用资源单位，代表远程大模型 API 调用额度。**Token 即货币**。

### 5.1 Token 定义与锚定

| 项目 | 说明 |
|------|------|
| 锚定 | 1 万 Token = $1（基于订阅价格折算） |
| 性质 | 社区内部交易机制，不用于赚钱，不兑换法币 |
| 生命周期 | 订阅配额月底清零，购买配额长期有效 |

### 5.2 用户订阅与消费

**订阅档位**：

| 档位 | 价格 | 月配额 | 多设备同步 | Skill 市场 | 硬件加速 |
|------|------|--------|------------|------------|----------|
| 免费版 | $0 | 0 | 仅单机 | 只读（不能下载） | ❌ |
| 基础版 | $10 | 10 万 Token | 2 台 | 限量下载 | ❌ |
| 专业版 | $20 | 30 万 Token | 5 台 | 不限量 | ✅（需购买硬件） |
| 企业版 | 定制 | 定制 | 定制 | 定制 | 定制 |

**Token 用途**：
- 调用远程模型：按实际消耗扣除
- 购买付费内容：支付给创作者（订阅式消费）
- 参与众筹：作为押金或贡献证明

**远程 API 策略**：
- 项目方统一采购 API（OpenAI、Claude 等）
- 用户消耗 Token 调用远程模型
- 用户也可自带 API Key（不消耗 Token，但也不计入社区贡献）

### 5.3 配额管理

用户可设置配额分配策略：
- 自动分配：系统自动从月配额扣除，不足时提示
- 保留配额：用户为远程调用设置保留额度（如 5 万 Token）
- 超限处理：月配额不足时，可选择：
  1. 从购买配额扣除
  2. 暂停内容订阅（按优先级）
  3. 通知用户充值

内容订阅优先级：用户可设置，配额不足时按优先级从低到高暂停订阅。

### 5.4 内容市场与创作者激励

**内容类型**：
- LoRA 权重：针对特定场景优化的模型权重
- Skill：可复用的工具/指令封装

**内容分类**：
- 免费内容：用户可免费下载使用
- 付费内容：需订阅付费（按月扣 Token）

**消费模式**：订阅式内容消费
- 免费试用期：7 天
- 扣费周期：按月（每月 1 日统一扣费）
- 随时取消：取消后停止下次扣费，已扣费用不退
- 满意保证：订阅后 3 天内取消可全额退款

**收益分成**：
- 平台抽成：30%
- 创作者获得：70%（以 Token 形式）
- 创作者 Token 用途：抵扣订阅费（1:1）
- **注**：V1.5 不支持创作者提现，仅限抵扣订阅费

**内容生命周期**：
- 新内容上架 → 默认 14 天试用期
- 连续 3 个月订阅数 < 10 → 下架警告
- 连续 6 个月订阅数 < 5 → 自动下架

### 5.5 内容加密与 DRM（V1.5）

**加密方案**：
- 内容文件使用 AES-256 加密
- 每个用户下载时，用该用户的公钥加密 AES 密钥
- 本地存储加密后的内容 + 加密的 AES 密钥

**订阅验证**：
- 本地缓存订阅凭证（有效期 24 小时）
- 凭证包含：内容 ID、过期时间、签名
- 离线时使用缓存凭证，最长可用 7 天
- 7 天后需联网刷新，否则内容禁用

**设备管理**：
- 用户可管理授权设备（专业版最多 5 台）
- 更换设备时需解绑旧设备
- 解绑后旧设备上的内容自动失效

**重装系统**：
- 用户需重新登录账号
- 已订阅内容自动恢复（重新下载解密）
- 无需重新付费

### 5.6 项目方收入与成本

**收入来源**：
- 用户订阅费（法币）
- 内容交易抽成（30%）

**成本结构**：
- API 采购：$2-3/百万 Token（混合模型成本）
- 基础设施：存储、带宽、中继服务器
- 研发与运营：团队人力、审核成本

**利润模型**：
- 基础版成本占比：20-30%
- 专业版成本占比：30-45%
- 交易抽成覆盖内容市场运营成本

## 6. 上层应用市场

### 6.1 需求投票板（V1.0）

用户可提交功能需求，其他用户投票支持。

**机制**：
- 用户提交需求（免费）
- 其他用户投票（免费）
- 项目方根据投票热度决定开发优先级
- 不涉及 Token 流转

### 6.2 内容市场（V1.5）

用户可上传/下载 LoRA 权重和 Skill。

**上传流程**：
1. 上传内容 + 元数据（描述、标签、定价，免费/付费）
2. 自动验证（沙盒测试、安全扫描）
3. 上架（标记“待审核”）
4. 人工审核通过后标记“已验证”

**下载流程**：
1. 浏览/搜索内容（可筛选免费/付费）
2. 查看详情（评分、下载量）
3. 免费内容直接下载；付费内容免费试用 7 天
4. 满意后订阅（按月扣 Token）

**安全机制**：
- 用户评分系统
- 评分过低自动下架
- 退款机制（3 天内全额退）
- 恶意内容永久封禁

### 6.3 社区与分享（V1.5+）

**分享功能**：
- 导出 Skill 配置为分享链接
- 分享“我的 AI 配置”（模型、LoRA、Skill 列表）
- 一键导入他人分享的配置

**社区功能**：
- 内置社区动态（新内容、热门 Skill）
- 用户可关注创作者
- 用户可评论和评分

**使用技巧**：
- 官方使用教程
- 用户贡献的 Tips & Tricks
- 场景化模板（如“程序员的一天”、“智能家居控制”）

### 6.4 众筹开发（V2.0）

用户可发起功能众筹，共同出资开发新功能。

**机制**：
- 用户发起需求，设定目标 Token 额度
- 其他用户用 Token 参与众筹
- 达到目标后，项目方负责开发
- 参与众筹的用户免费获得功能
- 未达到目标则全额退还 Token

**说明**：本版本不涉及“用户接力执行”的复杂模式，众筹仅作为需求优先级和资源池化的机制。

## 7. 安全与隐私

### 7.1 本地数据安全

| 数据类型 | 存储方式 |
|----------|----------|
| API Key | 系统钥匙串（Keychain/Windows Credential Manager） |
| 模型文件 | 只读权限，防篡改 |
| 用户数据 | 应用沙盒，其他进程无法访问 |
| 统计数据 | 本地存储，不上传云端 |

### 7.2 Skill 安全

- 沙盒运行：Skill 运行在 WebAssembly 或 Docker 容器中
- 权限模型：Skill 需声明所需权限（文件、网络、设备）
- 用户审批：首次运行需用户确认权限
- 代码审查：上传市场需人工审核

### 7.3 通信安全

- 设备间通信：TLS 1.3 + 证书绑定
- 身份验证：设备间共享密钥 + 签名验证
- 云端通信：API Key + JWT 令牌

### 7.4 隐私保护

- 数据不出本地：默认所有数据存储在用户设备
- 匿名贡献：用户可选择贡献训练数据（匿名化 + 差分隐私），需明确授权
- 透明披露：明确告知哪些数据会被收集、如何使用
- 用户控制：一键删除所有本地数据

## 9. 风险与应对

| 风险 | 严重程度 | 应对措施 |
|------|----------|----------|
| 用户订阅意愿低 | 高 | 免费版提供完整本地能力；7 天试用期；按量付费选项 |
| API 成本倒挂 | 高 | 控制订阅配额与成本比例；优先使用低成本模型；支持用户自带 Key |
| 内容质量失控 | 中 | 试用期机制让用户评估；评分系统自动筛选；人工抽审 |
| 内容盗版 | 中 | 加密分发 + 订阅验证；设备绑定；法律条款约束 |
| P2P 通信技术复杂 | 中 | 分期实现：先局域网，后互联网；使用成熟库（libp2p）；提供中继兜底 |
| 硬件供应链风险 | 中 | 初期使用开源硬件（树莓派）；自研前充分验证市场需求 |
| 本地训练硬件门槛 | 中 | 分层策略：仅支持有 GPU 用户；无 GPU 用户走云端训练（消耗 Token） |
| 竞争压力 | 低 | 差异化定位：本地优先 + 隐私保护 + 开源生态 |
