# The Damn Life 项目计划书 V0.5

> 本版本目标：在 **3-4 个月**内交付一个可长期使用的 **离线优先个人自动化助手（单机版）**，用清晰的“可验收闭环”验证价值，为后续局域网/市场/硬件演进打基础。

---

## 1. 一句话定位（V0.5）

**默认离线可用、可审计可控的个人自动化助手。**

核心承诺：
- **离线优先**：断网也能对话与执行核心任务
- **可控可审计**：每一次工具调用都有记录、可回放、可撤销（在可能范围内）
- **可扩展**：以 Skill 作为能力载体，后续自然生长为生态

---

## 2. V0.5 的产品边界（做与不做）

### 2.1 V0.5 必做
- 单机环境管理器（PC 优先，Windows 作为首要支持平台）
- 本地模型对话（可切换不同本地推理后端，但至少一种可用）
- Skill Runtime（最小可用）：结构化输入输出 + 权限声明 + 运行隔离 + 人机审批
- 任务执行闭环：计划 → 执行 → 结果 → 失败解释 → 审计记录
- 基础 UI：Web UI 或桌面壳（优先“可用”而非“完美”）

### 2.2 V0.5 明确不做（推迟到后续版本）
- 多设备同步、局域网发现与通信（V1.0+）
- 互联网 P2P、NAT 穿透、中继体系（V2.0+）
- Token 经济、内容市场、DRM、创作者分成（V1.5+）
- 本地 LoRA 训练（V1.5+，且仅高级用户）
- 语音唤醒/视觉识别（V2.5+ / V3.0+）

> 原则：V0.5 只做 **能形成口碑的闭环体验**，避免重基础设施拖慢验证速度。

---

## 3. V0.5 北极星场景（只打 3 个“硬场景”）

> 目标：让用户在真实日常里反复使用，而不是“能跑起来就结束”。

### 场景 A：本地文件与信息整理（离线强项）
- 诉求：整理下载目录、归档文档、重命名、提取摘要、生成索引
- 价值：离线可用、隐私安全、可审计（不会“莫名其妙删文件”）

### 场景 B：PC 自动化（本地工具调用的名片）
- 诉求：打开/关闭应用、启动脚本、管理窗口、打开网页、下载并归档
- 价值：强可感知、能展示 Skill 与权限体系的必要性

### 场景 C：本地日程/提醒（低依赖、可持续）
- 诉求：创建提醒、到点通知、查看今日事项、生成总结
- 价值：高频使用、无需云端依赖，适合积累“长期记忆/偏好”

> 其余需求都按“能否服务上述三场景”作为优先级过滤条件。

---

## 4. 系统组成（V0.5）

### 4.1 环境管理器（单机）
职责：对话入口、任务编排、Skill 调度、权限控制、审计记录、模型调度与降级。

### 4.2 本地个人 AI 助手（软件形态）
能力：本地对话 + 工具调用（通过 Skill Runtime），必要时可支持“手动配置远程模型”（可选、非默认）。

### 4.3 Skill Runtime（V0.5 最小实现）
Skill 是“环境要素交互方式”的打包形式，必须标准化与可审计。

---

## 5. 离线优先（V0.5 细化为可验收规则）

### 5.1 能力分级
- **核心能力（必须离线）**：对话、本地模型推理、已安装 Skill、任务记录查询
- **增强能力（联网可选）**：远程模型、下载扩展内容、同步

### 5.2 离线降级策略（验收项）
- UI 明确显示“离线模式”
- 任何需要联网的能力必须：
  - 可被替代为离线方案（若有），或
  - 明确提示不可用原因与恢复条件

---

## 6. Skill 规范（V0.5 基线）

### 6.1 Skill 包结构（建议）
- `manifest.json`：名称、版本、作者、入口、权限声明、参数 Schema
- `schema.json`：输入 JSON Schema（或直接内嵌于 manifest）
- `handler.(py|js)`：执行逻辑（V0.5 可先支持一种语言）
- 可选资源：图标、示例、测试用例

### 6.2 输入/输出约束
- 输入：JSON Schema 校验（必做）
- 输出：结构化结果 + 人类可读摘要（便于 UI 展示与审计）

### 6.3 最小权限模型（V0.5 必做）
以“默认拒绝”为原则，权限声明+审批+运行时约束三者必须同时存在。

权限维度（建议）：
- **filesystem**：目录白名单；只读/读写；是否允许删除；是否允许递归
- **process**：允许执行的命令白名单；是否允许启动 GUI 应用
- **network**：是否允许出网；域名白名单；是否允许上传
- **clipboard**：读/写
- **notifications**：发送通知

审批策略（建议）：
- 首次运行：展示权限清单 + 风险提示 + 允许/拒绝
- 高风险动作（删除、覆盖、批量操作、上传）：每次二次确认或临时授权（可设置有效期）

### 6.4 运行隔离（V0.5 可选其一先落地）
- 优先：Docker 隔离（Windows/开发阶段更易落地）
- 备选：受限子进程 + 系统权限控制（可作为无 Docker 环境的 fallback）

### 6.5 审计记录（V0.5 必做）
每次 Skill 调用必须记录：
- 调用时间、Skill 版本、输入摘要、输出摘要
- 权限使用情况（是否触发高风险动作、是否二次确认）
- 产生的副作用（尽可能结构化记录，例如写入/删除了哪些路径）

---

## 7. 任务执行闭环（V0.5 的“可用性核心”）

### 7.1 任务状态机（建议）
- `planned` → `running` → `succeeded` / `failed` / `cancelled`

### 7.2 失败可解释（验收项）
失败时必须给出：
- 失败原因（权限不足 / 文件不存在 / 命令错误 / 模型理解失败）
- 修复建议（授予权限 / 选择目录 / 重试 / 切换 Skill）
- 可重试入口（同参数重试或调整参数重试）

### 7.3 回放与撤销（V0.5 范围）
- **回放**：展示完整的“计划/执行/结果/证据”
- **撤销**：仅对可撤销动作提供（例如移动/重命名可回滚；删除若无回收站则提示不可逆）

---

## 8. 数据与隐私（V0.5）

### 8.1 数据默认本地
- 对话记录、审计日志、配置、模型文件、Skill 包均默认本地存储

### 8.2 机密信息存储
- API Key（若启用远程增强）：使用系统安全存储（Windows Credential Manager 等）

### 8.3 一键清除（验收项）
- 用户可一键删除：对话记录、审计记录、缓存与配置（模型文件可选）

---

## 9. 版本指标（V0.5 用来判断“值不值得继续扩张”）

> V0.5 不追求“功能多”，追求“可持续使用”。

建议指标（至少跟踪其中 4 个）：
- **任务成功率**：北极星三场景任务成功率 ≥ 85%
- **失败可解释率**：失败案例中，用户能理解原因并完成修复/重试 ≥ 70%
- **离线可用比例**：核心流程离线可用覆盖 ≥ 90%
- **平均任务完成时长**：典型任务（整理下载目录 / 打开工具链）可在 1-3 分钟内完成
- **崩溃恢复成功率**：推理或 Runtime 异常后自动恢复且不丢上下文 ≥ 95%

## 10. 路线图（从 V0.5 起的调整版）

### 10.1 总体路线图（建议）
| 版本 | 时间 | 核心交付 | 启动门槛（建议） |
|------|------|----------|------------------|
| V0.5 | 3-4 个月 | 单机闭环：离线对话 + Skill + 权限 + 审计 + 三场景可用 | 指标达标（见第 9 章） |
| V1.0 | 6-8 个月 | 局域网多设备（最小同步）+ 官方 Skill 库 + 更完善 UI | V0.5 留存稳定、Skill 数量与质量可控 |
| V1.5 | 9-12 个月 | 内容市场（先 Skill/模板，LoRA 作为高级项）+ 订阅增强 | 需要稳定的审核/签名/权限体系 |
| V2.0 | 12-18 个月 | P2P + 众筹开发 + 硬件扩展探索 | 生态增长确定、资金与运维可承受 |

> V1.0 先把“局域网多设备”做成“可感知便利”，而不是直接上复杂互联网 P2P。

## 11. 风险与应对（V0.5 视角）

| 风险 | 严重程度 | V0.5 应对策略 |
|------|----------|----------------|
| 做成“能演示但不好用” | 高 | 以三场景验收与指标约束，避免功能堆砌 |
| 工具调用不安全 | 高 | 最小权限模型 + 二次确认 + 审计记录（第 6 章） |
| 本地模型效果不足 | 中 | 任务分解与可重试；可选远程增强（非默认） |
| 工程范围失控 | 高 | 明确“不做清单”（第 2.2 节）与 DoD（第 12 章） |

---

## 12. V0.5 Definition of Done（DoD，交付验收清单）

以下条目全部满足才算 V0.5 完成：
- 能离线完成“三个北极星场景”的各 2 个典型任务（共 6 个任务）并可演示
- Skill 支持：安装/启用/禁用/卸载，且有版本号
- Skill 输入 JSON Schema 校验生效，非法输入被拒绝且有错误提示
- 权限系统生效：首次运行审批；高风险动作二次确认；拒绝后不执行
- Skill 调用审计记录完整可查询（含输入/输出摘要与副作用信息）
- 任务失败可解释：出现失败时能给出原因与可操作的修复建议
- 推理或 Runtime 崩溃后可自动恢复，不破坏审计记录
- 有基础 UI（Web/桌面壳）可完成上述流程，无需命令行介入
- 本地数据默认不出设备；提供一键清除入口

## 13. 技术选型建议（V0.5 取“可落地优先”）

| 模块 | 建议 |
|------|------|
| 本地推理 | llama.cpp（优先保证 Windows 可用） |
| 本地存储 | SQLite（对话/任务/审计/配置） |
| Skill Runtime | 先用 Docker 或受限子进程完成隔离；逐步演进到更强沙盒 |
| UI | 先 Web UI（迭代快），后续再封装桌面壳 |
